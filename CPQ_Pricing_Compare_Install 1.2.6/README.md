# CPQ Pricing Compare

Use this Chrome or Microsoft Edge extension to compare Old Pricing and New
Pricing for a test quote and download an Excel workbook. It runs in its own
browser tab so the comparison can continue while you switch tabs.

## Install once

1. Extract the ZIP to a folder you can keep.
2. Open `chrome://extensions` in Chrome or `edge://extensions` in Edge.
3. Enable **Developer mode**, choose **Load unpacked**, and select
   the extracted `CPQ_Pricing_Compare_Install` folder containing `manifest.json`.
4. Open **CPQ Pricing Compare** from the Extensions menu.

The extension is distributed as an unpacked folder. If your organization
blocks loading unpacked extensions, ask the browser administrator about
deployment. Java, a local server, and browser-side dependencies are unnecessary.

## Compare a quote

1. Enter the numeric BS Id. Select the first
   and second pricing scenarios. The defaults are Old Pricing then New Pricing.
2. Enter your test CPQ site URL and CPQ web-service credentials. On first use,
   allow the browser permission for that site when prompted.
3. Click **Compare & download Excel**. Keep the extension tab open until the
   download starts.

The SOAP request uses WS-Security UsernameToken.
The extension can save connection settings locally. Saved credentials are stored in this browser and sent over HTTPS to the selected CPQ origin.

## Save and switch sites

Choose **New site**, enter the site URL, username, and Commerce settings, and
click **Save site settings**. Select a saved site to restore its fields. Saving
the same URL updates that profile. Passwords are saved locally with their site profiles.

The HTTP SOAPAction headers are fixed to `updateTransaction` and
`getTransaction`. The **Pricing action** field inside the update payload
defaults to `oRCL_OSC_UpdateOpportunity`.

## Commerce settings

Defaults from the shared CPQ discussion are process `oraclecpqo`, header
`transaction`, action `oRCL_OSC_UpdateOpportunity`,
and SOAP toggle `pricingToggle_t_c`. Confirm the action triggers pricing and
the XML payload matches the input generated by your CPQ site. The pricing
action and request/response toggle names are editable. A site that requires a
different SOAP envelope or authentication flow needs an extension change.

The extension reads transaction XML from the update response when available.
It calls `getTransaction` when the update returns only status or lacks a usable
snapshot. If the update returns partial XML with the toggle, select **Always
retrieve a fresh transaction snapshot**. Each snapshot must confirm the
requested pricing toggle before the comparison continues.

Compare saves the same quote twice. The second update starts from the first
update’s saved state and leaves the quote in the second pricing mode. Use a
test quote. If an update fails or times out, check the current quote state
before retrying.

## Excel report

The workbook contains Doc Number, Attribute Name, Old Pricing Value,
New Pricing Value, and Status. The price columns keep their labels even if
you choose to run New Pricing first. Missing attributes or lines are Failed.
Underscore-prefixed fields, standard pricing and update timestamps, obsolete
attributes, and the toggle are excluded. Add site-specific exclusions under
**Commerce settings**. Values are compared as supplied by CPQ, including
numeric formatting and whitespace.

The Compare workflow and Excel export were checked with simulated CPQ
responses. The extension still needs a test in the target browser and CPQ site.


## Request context

The default request context is **Signed-in CPQ tab**. Open the selected CPQ
site in another tab and sign in before comparing. The extension sends SOAP
requests from that site's browser context with its session cookies, while
also providing the configured WS-Security credentials. Keep that CPQ tab open
until the operation finishes. Site access and the extension's scripting
permission are required.

The **Extension tab** mode remains selectable for sites supporting direct
extension requests. The extension never retries a failed update automatically.
An empty HTTP 403 response does not establish the reason for rejection.

## Long attribute values

Comparison uses the complete values. A value exceeding Excel's cell limit is
stored in numbered parts on the Long Values worksheet. Its Comparison cell
identifies the worksheet rows containing the complete value. Join the parts
in their displayed order to reconstruct the original text.
